# DuoTrack

通过自己的公网服务器，让一台 Windows 电脑的键盘和鼠标控制另一台电脑。

## 用户体验

- 客户端是窗口和系统托盘程序，不需要命令行
- 每台电脑首次启动自动生成设备身份，私钥由 Windows 当前用户加密保护
- 用户不需要填写或保存共享密钥
- 一台电脑生成 6 位一次性配对码，另一台输入即可配对
- 配对完成后，从在线设备列表中点击“控制”
- `Ctrl+Alt+F12` 可快速开始或停止控制
- 支持左右上下屏幕布局、边缘进入远端和从连接边缘返回本机
- 同一局域网自动发现已配对设备并通过双向认证的 TLS 直连，键鼠数据不经过公网中继
- 支持开机自动启动、自动重连和断线释放按键

当前仅支持 Windows 客户端。普通权限程序不能控制 UAC 安全桌面、登录界面或权限更高的程序。

### 触控板

两指上下/左右滚动保留精细增量，仅合并同一个不超过 4ms 的采集分组；合并后的增量最多为一个滚轮刻度（120），原始大增量不截断。不同分组、方向、轴及按键/点击/释放消息不会合并。接收端立即处理，不设置滚动播放队列，鼠标不等待额外播放时钟。客户端只过滤 DuoTrack 自己标记的模拟输入，触控板驱动生成的滚轮与快捷键仍可转发。

在支持微软精确触控板接管接口的 Windows 11 系统上，控制远端时支持三指左/右切换窗口、上滑任务视图、下滑显示桌面。设置区会显示本机是否支持。控制期间启用透明前台输入窗口来接收系统手势，返回本机后隐藏并恢复原来的前台窗口。手势发送为普通快捷键，无需更新中继协议。旧系统或不支持该接口的设备仅支持驱动输出的快捷键；不会修改用户的全局触控板配置。三指动作按一次完整滑动执行一次，不复制系统的连续窗口选择动画。

两指滚动通过 Win32 输入窗口或低级鼠标钩子捕获系统产生的滚轮消息，具体入口取决于 Windows 输入路径。没有自行解析两指接触点或生成额外惯性。保留滚轮精度和有边界的队列合并；原生捏合缩放尚未转发。

该接口目前被微软标记为实验性，使用了运行时能力检测；参考 [微软精确触控板编程指南](https://learn.microsoft.com/en-us/windows/win32/input-precisiontouchpad/precision-touchpad-guide)。客户端仍使用 .NET 8，Windows SDK 引用固定为兼容 .NET 8 的 `10.0.26100.86`，基础运行要求为 Windows 10 1809 或更高版本；原生三指接管需系统实际支持对应 API。

## 一次性部署服务器

要求：

- 一台安装了 Docker Engine 和 Docker Compose 的 Linux 服务器
- 一个解析到服务器的域名，或者服务器的固定公网 IP
- 公网开放 TCP 80、TCP/UDP 443

上传本目录到服务器，然后执行：

```bash
cd DuoTrack
chmod +x install.sh
./install.sh 43.139.208.28
```

安装脚本会保存域名或公网 IP、构建中继服务并启动内置 Caddy。Caddy 使用 Let’s Encrypt 的短期证书配置，自动申请和续期域名或公网 IP 的 HTTPS 证书；SQLite 数据库、设备身份和配对关系存放在 Docker 数据卷中。

验证：

```bash
curl https://43.139.208.28/health
docker compose ps
docker compose logs --tail=100
```

正常应返回：

```json
{"status":"ok"}
```

以后更新服务端：

```bash
docker compose up -d --build
```

## 客户端使用

1. 在两台电脑运行 `DuoTrack.Client.exe`。
2. 填写同一个服务器地址，例如 `https://43.139.208.28`，设置电脑名称，点击“保存并连接”。地址只需填写一次。
3. 在第一台点击“生成配对码”。
4. 在第二台输入这组 6 位配对码并点击“使用配对码连接”。
5. 刷新设备列表，选择在线设备并点击“控制”。
6. 按 `Ctrl+Alt+F12` 返回本机；再次按下可继续控制当前选择的设备。

第一次测试时，建议在被控制电脑旁保留备用键鼠。

### 屏幕布局与自动切换

在操作端选择已配对的设备，在“屏幕布局”中点击左、右、上、下方位，勾选“像扩展屏一样，用鼠标跨屏切换”。设备和布局会自动保存，重启后恢复。当前布局支持本机与一台选中的远端电脑。

例如另一台电脑在右侧：本机鼠标移到最右侧边缘后进入远端左侧；从远端左边缘向左移动即可返回本机。光标沿连接边缘的位置会按两台屏幕的分辨率比例映射。也可随时在操作端按 `Ctrl+Alt+F12` 返回。

自动切换默认关闭，目标离线时不切换；开启后无论从边缘还是按钮进入远端，都可以从连接边缘返回。光标落在边界内侧 1 像素，不需要等待冷却即可再次跨屏。本机有多个显示器时，内部相邻边界不触发电脑切换。

本功能扩展了输入协议。升级时需要同时更新中继服务和两台 Windows 客户端，然后执行 `docker compose up -d --build` 重建中继服务。保留现有数据卷即可继续使用原来的配对关系。

### 局域网直连

两台电脑运行新版客户端并连接更新后的服务器一次，即可自动同步原有配对设备的公钥，不需要重新配对。之后同一 IPv4 子网中的设备会自动发现彼此并建立 TLS 直连；设备列表显示“局域网直连”。每次开始控制时优先选择直连，所有键鼠和边缘返回数据都通过本地连接传输。互联网中继只作为备用，不参与该直连会话的输入转发。

已缓存配对身份后，即使公网服务器不可用，客户端也能在局域网中发现、连接并控制对方，包括退出客户端后重新启动。首次配对、首次同步公钥仍需服务器；本阶段没有加入完全离线的首次配对。

发现使用 UDP 45731 广播；加密连接通常使用 TCP 45732（端口占用时选择临时端口并自动广播）。第一次运行时，在 Windows 防火墙提示中允许 DuoTrack 通过“专用网络”。两台电脑需要能相互访问；访客 Wi-Fi、AP 隔离或禁用广播的网络可能无法直连，此时使用公网中继。当前自动发现支持 IPv4，不支持跨子网发现。

连接使用设备原有 ECDSA 身份进行双向 TLS 公钥验证。广播只提供地址提示，不会把广播里的设备自动加入信任列表。缓存按服务器地址隔离。直连中断时会停止当前控制并释放按键；再次跨屏会选择可用线路，避免重放已经送达的点击或按键。控制过程中不自动迁移正常工作的会话；直连稍后就绪时，下次开始控制会使用直连。

设备列表和配对同步仍可在后台访问公网服务器；“局域网直连”指键鼠数据路径，不是彻底禁止客户端发起公网请求。

## 编译与发布

需要 .NET 8 SDK 或更高版本：

```powershell
dotnet build .\src\DuoTrack.Relay\DuoTrack.Relay.csproj -c Release
dotnet build .\src\DuoTrack.Client\DuoTrack.Client.csproj -c Release

dotnet publish .\src\DuoTrack.Client\DuoTrack.Client.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:DebugType=None -o .\publish\win-x64-single
```

本机启动开发服务器：

```powershell
dotnet run --project .\src\DuoTrack.Relay\DuoTrack.Relay.csproj `
  --urls http://127.0.0.1:18080
```

客户端服务器地址填写 `http://127.0.0.1:18080`。

运行完整服务端集成测试：

```powershell
.\scripts\integration-test.ps1
dotnet run --project .\tests\TransportTests\TransportTests.csproj -c Release
dotnet run --project .\tests\TouchpadTests\TouchpadTests.csproj -c Release
```

原生触控板集成测试可添加 `-- --native`，会短暂启用透明前台输入窗口，并向该测试窗口注入模拟两指/三指输入；测试结束后恢复之前的窗口和鼠标位置。

### 输入延迟优化与诊断

输入钩子、原生触控板输入窗口和接收端注入在独立 STA 输入线程上运行，界面布局/刷新不会阻塞输入处理。滚动首包直接发送，不固定等待合并窗口。采集分组同时受 Windows 消息时间和单调观察时钟约束（4ms）；分组标识写入滚动包专用 Flags 字段，最高位为标记，低位仅比较相等，不用于延时播放或跨机校时。发送、接收两端均限制同组内合并最多 120；没有分组标记的旧端输入不再二次合并。局域网仍可将同一目标最多 64 帧一次写入 TLS。固定包大小和中继协议不变，两台客户端都需更新才能完整生效，服务器无需重建。设备列表和配对缓存只在实际变化时更新。

设置区显示“本机排队 P95”，用于观察本机发送队列、接收注入队列中最近输入的等待时间。该数据不包含网络、远端应用处理或屏幕刷新延迟，不能当作两台电脑之间的总延迟。性能统计只保存耗时和计数，不记录按键内容。传输测试会打印本机回环的首包耗时、排队时间和批量写入次数；实际 Wi-Fi/公网效果需在两台设备上验证。

### 滚动诊断

出现页面跳动后，用快捷键返回，在两台客户端分别点击“导出滚动诊断”保存 JSON。内存环形缓冲记录最近 16384 条滚动记录，包括窗口/钩子捕获、网络发送前、LAN/中继收到、SendInput 调用前后，以及滚动量、轴、采集分组和调用耗时。不记录按键、输入文字、鼠标位置、设备身份或服务器凭据；仅点击导出时写文件。两端本地时间不可直接相减；SendInput 返回也不代表页面已经绘制。

队列回归测试：`dotnet run --project tests/TouchpadTests -c Release -- --queue-regression`。原生采集入口诊断：追加 `-- --capture-diagnostics`，需要前台激活，无法激活时会明确输出 SKIP。测试覆盖不同采集组不会因线程暂停而合并、同组突发有界、距离守恒及高负载后的鼠标响应；最终手感仍需真实触控板和目标应用验证。

#### 被控端输入注入阻塞的对照诊断

设置中提供“诊断：独立线程注入（重启生效）”，默认关闭，保留共用输入线程的行为。开启后，钩子和触控板窗口使用另一条 STA 消息线程，接收事件仍按原顺序在原输入线程上处理。没有新增滚动播放缓冲或改变滚动增量。钩子线程不等待注入线程；退出时先释放注入按键，再关闭钩子线程。

仅需替换被控端客户端，主控和服务器无需更新。测试前从系统托盘退出旧客户端，确保只启动一个实例。先保持开关关闭，在同一个应用里短暂滚动 1–2 秒，返回主机后导出 `shared.json`；然后开启开关，从托盘退出并重新打开，确认“当前模式：独立线程注入”，在同一个应用重复并导出 `isolated.json`。不要在有积压时反复滚动，以免把更多事件加入队列。关闭窗口只会隐藏到托盘，不算重启。

诊断版本标识为 `hook-isolation-2026-10-28`。JSON 增加实际启动模式 `InjectionMode`、记录线程 `ThreadId`，以及自身注入滚轮进入鼠标钩子和 `CallNextHookEx` 返回的记录。钩子记录的 `Frame=0`，因为原生固定注入标记不携带网络分组编号；不能据此与网络事件按 Frame 关联。后续钩子调用耗时不等于 DuoTrack 自身处理耗时；缺少钩子记录也不能单独证明钩子已超时。该版本用于定位故障，不代表已证明或修复用户设备上的约一秒阻塞。

线程隔离回归：`dotnet run --project tests/TouchpadTests -c Release -- --thread-isolation` 和追加 `--isolated`。测试实际窗口的线程配置、模拟注入线程阻塞时钩子线程的响应、日志模式和退出清理；不注入真实输入，不修改用户保存的设置。它不能替代真实设备的 SendInput 对照测试。

### 三指手势接管恢复

`gesture-focus-2026-10-28` 版本修复主控端接管失效后没有恢复的问题：开始控制时确认 DuoTrack 实际处于前台；控制期间监听 `WM_ACTIVATEAPP` 并以 150ms 间隔检查前台进程。失去前台后取消未完成的三指识别并尝试恢复，每轮最多三次；Windows 拒绝前台激活时显示“手势暂停”，冷却两秒后新的鼠标/键盘操作可触发下一轮。停止控制后停止检查和恢复，也不会把用户已经切换到的其他程序重新切走。恢复动作在钩子回调之外执行，接收端独立注入线程和滚动策略不变。

此次只需更新使用触控板的主控端，服务器和已验证顺滑的被控端无需更新。设置区手势状态区分就绪、已接管、恢复中、暂停和接口不可用。仅支持三指滑动，不新增三指轻点。Windows 仍可能拒绝前台切换，恢复之前的手势可能由本机系统处理；此时先用快捷键返回，打开 DuoTrack，再开始控制。

`TouchpadTests` 默认覆盖接管状态回归；`-- --gesture-native` 可选验证原生三指方向映射，无法获得前台时明确跳过，不把跳过当作通过。状态回归不能替代两台真实设备上的最终验证。

## 安全说明

- 设备通过 ECDSA P-256 签名挑战进行认证，不使用所有设备共享的 Token。
- 配对码 5 分钟失效、使用一次即删除，并限制尝试频率。
- 服务端只向已经配对的设备转发输入。
- 公网连接通过 Caddy 使用 HTTPS/WSS。
- 局域网直连使用 TLS，并固定验证已配对设备的公钥。
- 公网中继模式的输入载荷会在自己的服务器上解密后转发，尚未实现中继模式下的设备到设备端到端加密。因此中继应部署在自己信任的服务器上。局域网模式由两台设备直接建立 TLS 加密连接。
