# 2026-10-27

## DuoTrack 代码评审（架构 + 代码质量）

项目概况：.NET 8 键鼠跨机控制工具。三项目 + 五测试程序，生产代码约 3750 行、测试约 710 行。

分层：
- `src/DuoTrack.Protocol` — 线格式 `InputPacket`（13B）/ `RelayWire`（30B 单帧、19+13n 批量、9B ping）
- `src/DuoTrack.Relay` — Minimal API 单文件 `Program.cs`，SQLite，配对码，WS 转发
- `src/DuoTrack.Client` — WPF + Win32 钩子，独立 STA 输入线程，LAN mTLS 直连

评审结论要点：
- 优点：零编译告警；协议紧凑且向后兼容（subprotocol 协商）；测试跑真实 TLS/真实 socket，覆盖 2048 帧顺序、伪造证书拒绝、配对缓存并发失效；私钥 DPAPI 保护、公钥固定（SPKI base64 比对）、自注入回环过滤（ExtraInfo tag）。
- 主要问题：
  1. Relay 未启用 `UseForwardedHeaders`，在 Caddy 后 `RemoteIpAddress` 全是容器 IP → 限流退化为全局单桶。
  2. `SessionStore` / `challenges` 无过期清理，客户端每 3s 重连会不断新建 session token → 服务端内存泄漏。
  3. `MainWindow.xaml.cs` 544 行 God Object：UI + 跨屏状态机 + 注入 + 设置混在一起。
  4. 大量 `Async` 后缀方法实为同步返回 `Task.CompletedTask`；`async void` 事件处理器。
  5. 无 .sln / .editorconfig / CI；测试是 Console + throw，非 xunit。
  6. README 仍写需要开放 80 端口，但 compose/Caddyfile 已改用 TLS-ALPN（文档过时）。
  7. Dockerfile 用 .NET 8 非 root 用户 + 具名卷 `/data`，权限是否可写需实测。
- 构建注意：本机 `dotnet restore` 报 `Value cannot be null (Parameter 'path1')`（NuGet 目标），属环境问题；改用 `dotnet build --no-restore` 可正常编译，0 警告 0 错误。
